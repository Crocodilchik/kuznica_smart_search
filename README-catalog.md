# Разработчик 3: каталог и поиск Softline

Реализован самостоятельный Python-блок по [распределению ролей](project-agent-roles.md):
потоковый разбор YML/XML и gzip, EDA, нормализованный каталог, точный поиск по SKU,
Qdrant BM25 с жёсткими фильтрами, интерфейсы dense/hybrid и RRF.
Разбор пользовательского намерения и рекомендация сопутствующих товаров относятся к другим блокам.

## Быстрый запуск в Windows PowerShell

Локальное окружение находится в `.venv`; активация не обязательна. Команды выполняются из корня проекта.

```powershell
& '.\.venv\Scripts\python.exe' -X utf8 -m softline_search search 'Kaspersky Endpoint Security' --compact
& '.\.venv\Scripts\python.exe' -X utf8 -m softline_search search 'антивирус' --in-stock --max-price-kopecks 10000000 --compact
& '.\.venv\Scripts\python.exe' -X utf8 -m softline_search search 'AL16-03SWS701-0100' --mode sku --compact
& '.\.venv\Scripts\python.exe' -X utf8 -m pytest -q
```

Суммы в параметрах и карточках — **целые копейки**. `10000000` означает 100 000 ₽.
Пустой SKU не подменяется идентификатором предложения. Для него есть `Catalog.get_product(product_id)`.

## Что подготовлено

- [EDA](reports/eda.md), [машинный отчёт](reports/catalog_profile.json).
- `data/catalog/catalog.sqlite` — полный каталог с индексом SKU.
- `data/catalog/products.jsonl` — все нормализованные карточки, по одной на строку.
- `data/catalog/sample_products.jsonl` — воспроизводимый срез для остальных разработчиков.
- `data/catalog/categories.json` — исходное дерево категорий с путями и идентификаторами предков.
- `data/catalog/category_aliases.json` — соответствия имён вроде `endpoint_security` фактическим категориям.
- `data/catalog/attributes.json` — справочник атрибутов, покрытие и примеры значений.
- `data/qdrant/index.json` — активная коллекция, используемый BM25-механизм и состав индекса.
- [JSON Schema контрактов](schemas/) и [инструкция интеграции](docs/INTEGRATION.md).

Срез включает разные верхние категории, а не первые несколько сотен строк фида.
Показатели EDA и доступность относятся к дате выгрузки, а не к текущему состоянию магазина.

Проверка 26.11.2026: полный каталог и индекс содержат **136 040 предложений** из **9 311 категорий**.
Прошли **39 автоматических тестов** и [8 сценариев на реальных данных](reports/smoke_results.json).
В этом замере первый BM25-запрос с загрузкой индекса занял 16,3 с; следующие BM25-запросы — 4,1–5,7 с.
SKU — около 1 мс. Это функциональная проверка и замер на данном ПК, без оценки NDCG или коммерческого эффекта.

## Подготовка с нуля

На другом ПК сначала создайте venv установленным Python 3.12+, затем установите окружение:

```powershell
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.lock.txt
& '.\.venv\Scripts\python.exe' -m pip install -e . --no-deps --no-build-isolation
& '.\.venv\Scripts\python.exe' -X utf8 -m softline_search prepare 'data/raw/Mindbox.yml.gz.xml'
& '.\.venv\Scripts\python.exe' -X utf8 -m softline_search index
```

Исходный файл скопирован в `data/raw`, оригинал в Downloads не изменяется.
Сжатие определяется по первым байтам: расширение `.gz.xml` не считается признаком gzip.
Новая индексация создаёт отдельную коллекцию и публикует её после успешной загрузки всех батчей.
При перестроении старый индекс остаётся на диске. Каждая локальная сборка получает отдельное хранилище;
при открытии поиска загружается только активная сборка из `index.json`.
Для пакетной записи новой коллекции используется SQLite WAL; перед публикацией выполняется checkpoint.
Файлы установленного Qdrant SDK не изменяются.

## BM25 и производительность

По умолчанию `index` проверяет **нативный полнотекстовый BM25 со scoring** в доступном Qdrant.
Если механизм не поддерживается, используется официальный FastEmbed `Qdrant/bm25`
со sparse-индексом и вычислением IDF на стороне Qdrant. Вручную алгоритм BM25 не переписан.
Для обоих вариантов русский стемминг и нормализация применяются одинаково к документам и запросам.
Версии, числа и латинские названия сохраняются; цена не входит в поисковый текст отдельным фактором.

Local mode работает без Docker, сервера, GPU и внешних API. Он удобен для разработки;
полнотекстовый поиск в нём пересчитывает статистики по корпусу при запросе. Для ускорения на этом ПК
можно построить sparse-вариант в отдельном хранилище и сравнить измеренные задержки:

```powershell
& '.\.venv\Scripts\python.exe' -X utf8 -m softline_search index --backend sparse --output data/qdrant-sparse
& '.\.venv\Scripts\python.exe' -X utf8 -m softline_search search 'антивирус' --index data/qdrant-sparse --compact
```

Поддержан и серверный режим: задайте `QDRANT_URL` (и `QDRANT_API_KEY`, если требуется) **до индексации**,
затем используйте те же настройки при поиске. API-ключ не сохраняется в манифестах.

Ссылки: [нативный BM25 по текстовому полю](https://qdrant.tech/documentation/search/text-search/full-text-search/),
[sparse BM25](https://qdrant.tech/documentation/inference/inference-bm25/).

## Dense и hybrid

Основной подготовленный индекс содержит BM25. Нейронные веса не загружаются автоматически.
`dense` без модели/векторов возвращает `unavailable`, `hybrid` с единственной работающей веткой —
`partial` с объяснением. BM25 не выдаётся за семантический поиск.

При наличии вычислений можно построить отдельный индекс с поддерживаемой FastEmbed моделью:

```powershell
& '.\.venv\Scripts\python.exe' -X utf8 -m softline_search index --output data/qdrant-hybrid --dense-model 'sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2'
& '.\.venv\Scripts\python.exe' -X utf8 -m softline_search search 'защита рабочих компьютеров' --mode hybrid --index data/qdrant-hybrid --dense-model 'sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2' --compact
```

Эта операция требует загрузки весов. Для документов и запросов проверяются одинаковые имя и размерность модели.
Интеграция dense/RRF проверяется тестовым векторизатором; качество нейронного поиска требует отдельной оценки.

## Ограничения данных и бюджета

- `0.00` преобразуется в `null`, а не в бесплатную покупку.
- Повторяющиеся `param` сохраняются списками; заглушки исключаются из `search_text`.
- `country` остаётся неизвестным без явного поля страны. Бренд и запись в реестре ПО не подменяют это поле.
- `К-во пользователей до` и «от 10 до 50» не превращаются в ёмкость пакета.
- `devices` допускает только известный пакет на нужное число **устройств**; пользователи, ядра и лицензии без
  известного соответствия устройствам не эквивалентны компьютерам.
- Поиск не предполагает возможность линейно умножить цену на нужное число лицензий.
- Учитывается известная минимальная покупка. Проверка правил лицензирования и состава заказа остаётся в Validation.
- При `budget_scope=bundle` цена отдельной позиции — необходимый предварительный фильтр;
  сумма всего комплекта требует проверки другим блоком и явно отмечается предупреждением.
- Политика «минимум 4 товара» принадлежит Supervisor/Validation: поисковый блок не добавляет нерелевантные позиции.

Тесты проверяют эти свойства и работу обоих BM25-механизмов. Они не являются экспертной разметкой релевантности.
Для Precision@4/NDCG@10 нужна разметка кандидатов, согласованная командой.
