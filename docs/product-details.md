# Подробности о товаре в AI-помощнике

## Как пользоваться

1. Напишите «Мне нужна мышь». Чат покажет до трёх пронумерованных карточек.
2. Напишите «Расскажи подробнее про первый вариант», «Подробнее про №2» или назовите модель, например «Logitech M190», если она есть среди показанных карточек.
3. В ответе появятся название, артикул, краткое описание, до трёх характеристик и ссылка «Открыть товар». Цена и наличие выводятся при наличии этих полей в каталоге.
4. Чтобы посмотреть другую карточку из того же списка, укажите её номер. Ответ с описанием сохраняет привязку к списку.

Без предыдущего списка можно написать «Расскажи подробнее про Logitech M190» или «Подробнее про артикул 910-005905». Если под названием найдено несколько предложений, помощник покажет варианты уточнения. Ответьте, например, «Расскажи подробнее про артикул 910-005905». Обычная просьба о подборе, изменении бюджета или поиске альтернативы продолжит выполняться как поиск.

## Как агент определяет карточку

1. После поиска Supervisor формирует порядок показа. Сначала идут рекомендации, затем основные товары. В ответах с альтернативами или дополнениями показываются только рекомендации. Исходная карточка исключается из списка для нумерации. Повторяющийся `product_id` занимает одну позицию. Чат получает до трёх ID в `chat_product_ids` и использует этот порядок для нумерации.
2. FastAPI сохраняет в Redis снимок сессии. Запись содержит `request_id` ответа, порядок ID, названия, бренды и артикулы. Следующая реплика из чата содержит `reference_request_id` именно этого ответа. Сервер проверяет снимок в пределах указанной сессии и последних 20 сохранённых поисковых ходов. Публичный API истории сессии сохраняет прежний формат.
3. Ветка `route_details` в LangGraph распознаёт запрос и вызывает `get_product_details`. Номер разрешается в ID, точный артикул — через индекс артикула в SQLite. Эти операции без открытия Qdrant. Для имени, не найденного в показанном списке, используется до 12 кандидатов BM25 с проверкой совпадения токенов названия. Это ограниченный поиск, поэтому при отсутствии однозначного совпадения помощник запрашивает артикул. Факты берутся из повторно прочитанной карточки SQLite.
4. Описание очищается от HTML и ограничивается 350 символами. При отсутствии описания используются известные характеристики. Ссылка ведёт на HTTPS-адрес из карточки. Цена в контракте выражена в копейках. DeepSeek не участвует в этой ветке.

## Результаты и поведение при сбоях

| Статус | Когда возвращается | Что видит пользователь |
|---|---|---|
| `ok` | Найдена одна карточка, есть описание или характеристики и безопасная ссылка | Компактный блок с товаром |
| `partial` | Карточка найдена, но отсутствует описание с характеристиками или безопасная ссылка | Доступные сведения и пояснение |
| `clarification_needed` | Номер вне списка, снимок истёк, модель не определена или у неё несколько предложений | Вопрос с просьбой указать существующий номер, название или артикул |
| `empty` | Карточка удалена либо точный артикул отсутствует | Сообщение, что товар не найден |
| `unavailable` | Ошибка обязательной зависимости для выбранного пути | Предложение повторить запрос |

У снимков тот же TTL, что у сессии Redis, по умолчанию 24 часа. Если Redis недоступен, числовая ссылка временно не разрешается. Явный артикул по-прежнему можно проверить напрямую по каталогу. В Streamlit доступны запросы с явным названием или артикулом.

## Диагностика и проверка

- В `steps` ответов о товаре указывается `route:product_details`, затем при вызове инструмента один из шагов `details:by_id`, `details:by_sku`, `details:by_name`.
- Лог `product_details.completed` содержит статус, последний шаг, коды причин и время выполнения. По нему можно измерять частоту уточнений и p95 отдельно для чтения по ID, артикула и поиска по имени. Временной интервал начинается внутри Supervisor, поэтому получение снимка в API в это измерение не входит.
- Запросы о подробностях не создают `search.completed`. Счётчики и доли пустых результатов обычного поиска сохраняют прежний смысл.
- Для проверки используйте один и тот же `session_id`. Сделайте поиск с `channel: "chat"`, затем передайте `request_id` ответа как `reference_request_id`. Проверьте, что `product_details.product_id` совпадает с выбранной позицией `chat_product_ids`. Повторите с другой сессией и убедитесь, что сервер запросил уточнение.
